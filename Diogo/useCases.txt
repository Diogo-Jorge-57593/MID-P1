| Term | Definition |
|---|---|
| Stakeholder | Person or group affected by system or interested in its results. |
| User requirement | Need or task described from user’s perspective. |
| Functional requirement (FR) | Behaviour or capability system must provide. |
| Non-functional requirement (NFR) | Quality or constraint system must satisfy. |
| Use case | Interaction between actor and system to achieve specific goal. |
| Client | Bank customer who owns accounts and may submit credit applications. |
| Account | Banking entity belonging to client and associated with transactions. |
| Transaction / movement | Recorded incoming or outgoing amount associated with account. |
| Credit application | Client’s request for credit, including requested amount, term and status. |
| Credit officer | Employee responsible for reviewing and updating credit applications. |
| Bank manager | Stakeholder monitoring credit activity and employee performance. |
| Application status | Current application state: pending, approved or declined. |
| Status history | Chronological record of application status changes. |
| Requested amount | Amount client requests; distinct from approved or disbursed amount. |
| Data source | Independent location or format storing information, such as MongoDB or CSV. |
| Data integration | Combining related information from heterogeneous sources. |
| Identifier | Unique value identifying entity, such as client ID or account ID. |
| Traceability | Ability to link requirements to stakeholders, use cases and verification. |
